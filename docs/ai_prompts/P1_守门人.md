===== 一、游戏是什么 =====
2D 横版单屏竞技场 Roguelike，1280×720，无重力无跳跃，8 向自由移动。
核心限制：玩家只能向【正右方】开炮，不可瞄准。
循环：赢了 → 三选一强化【敌人】→ 进下一轮；输了 → 三选一强化【玩家】→ 重打本轮。
终局：打满 8 轮结算，评级按总失败次数（S 0-2 / A 3-4 / B 5-7 / C 8-12 / D 13+）。

===== 二、三条不能动的设计规则 =====
1. 只有胜利才推进轮次；失败重打本轮。
2. 评级按总失败次数（抑制"故意送死刷 buff"的唯一锁扣）。
3. 词条是平铺单池，无前置解锁（GDD 里的"链"只是策划的设计辅助，不进游戏）。

- 判空用 GodotObject.IsInstanceValid(node)，绝对不要用 node == null（Godot 里销毁的节点不是 null）。
- 移动/碰撞 → _PhysicsProcess；UI/动画/输入 → _Process。
- 数值一律从 Resource (.tres) 读，不要在代码里写魔法数字。
- 所有面向玩家的文字走 GameManager.I.T("key")，读 data/strings.tres。

===== 七、⚠️ 三个必死的坑（都真实发生过） =====
1. 【场景文件名必须一字不差】Main 是按路径常量自动挂的（src/Data/RunConfig.cs 里的
   ScenesPath 常量）：
     Scenes/ui/hud.tscn            根节点 CanvasLayer，挂脚本 src/UI/Hud.cs
     Scenes/ui/upgrade_picker.tscn  根节点 CanvasLayer，挂脚本 src/UI/UpgradePicker.cs
     Scenes/ui/result_screen.tscn   根节点 CanvasLayer，挂脚本 src/UI/ResultScreen.cs
   三个根节点都必须是 CanvasLayer（脚本已经继承 CanvasLayer）。
2. 【ProcessMode 设错界面会冻住，而且没有任何报错】
   Godot 4 的枚举：Pausable = 只在【未暂停】时跑；WhenPaused = 只在【暂停】时跑；Always = 都跑。
   - 三选一弹窗：必须 WhenPaused 或 Always，否则 Paused=true 时界面点不动。
   - HUD：必须 Always（战斗中要刷新，暂停时也要看得见）。现已是 Always，别改回 WhenPaused。
   - 结算界面：必须 Always（结算发生在非暂停状态，WhenPaused 收不到 RunFinished）。
3. 【三选一没做完时游戏会自动跳过，这是正常的】
   项目里有 src/UI/AutoUpgradeFallback.cs 兜底：你的 upgrade_picker.tscn 一旦存在，
   它自动不启用；不存在时它自动跳过选择，保证主循环不卡死。
   看到控制台打 "[兜底] 三选一 UI 尚未制作，自动跳过" 不是 bug，不要去"修"它。
