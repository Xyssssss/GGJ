===== 一、游戏是什么 =====
2D 横版单屏竞技场 Roguelike，1280×720，无重力无跳跃，8 向自由移动。

===== 二、三条不能动的设计规则 =====
1. 只有胜利才推进轮次；失败重打本轮。

===== 七、⚠️ 六个必死的坑（都真实发生过） =====
1. 【Velocity 只允许在一处写】EnemyBase._PhysicsProcess 里就三步：
     ① 合成所有速度效果（ComposeVelocity）→ ② 反射（ArenaBounds.Reflect）→ ③ MoveAndSlide
   加任何速度类效果都塞进 ComposeVelocity()，❌ 不要在别处写 Velocity。
   多处写是本项目最容易出的 bug，表现为敌人乱窜或反射失效。
2. 【反射的方向判断不能省】必须 `if (p.X <= min.X && v.X < 0f) v.X = -vx;` 这样带方向判断。
   省了敌人会贴着边界反复取反，剧烈抖动。ArenaBounds.Reflect 已经写对了，直接用别重写。
3. ❌【不要给敌人水平速度分量设下限】（|vx| ≥ 速度×0.35 之类）。
   这个方案已被策划明确否决，别加回来。玩家可 8 向自由移动，能主动走到敌人轨迹上。
4. 【对象池复用必须重置状态】敌人是从池里复用的。我在 EnemyBase.Configure() 里加新字段时，
   **必须在 Configure() 里显式重置**。已经踩过：残留的无敌计时器让新刷出的敌人"打不死"
   （子弹照样销毁，但血量不掉）。现已有 _health.ClearInvincible() 与 _bounceCount = 0 作示范。
5. 【玩家碰撞只能用 Area2D 受伤盒】Player.CheckContact 用的是 Area2D + 每帧
   GetOverlappingBodies()。❌ 不要改回 GetSlideCollisionCount()：
   玩家静止时自己的 MoveAndSlide 速度为 0，检测不到撞上来的敌人，会**漏伤害**。
6. 【波次是定时推进的】到点就刷，不等上一波清完（刻意的压迫感，GDD §3.7）。
   ⚠️ 计时器必须在 SpawnWave() 末尾重置（现已是）。若留给下一帧去减，
   `0 - delta < 0` 会立刻再刷一波，表现为"第一波和第二波同时出现"。
