===== 一、游戏是什么 =====
2D 横版单屏竞技场 Roguelike，1280×720，无重力无跳跃，8 向自由移动。
核心限制：玩家只能向【正右方】开炮，不可瞄准。
循环：赢了 → 三选一强化【敌人】→ 进下一轮；输了 → 三选一强化【玩家】→ 重打本轮（轮次不前进）。

===== 二、三条绝对不能动的设计规则 =====
1. 只有胜利才推进轮次；失败重打本轮。

===== 六、抽取逻辑的验收标准（GDD §4.3） =====
- 平铺单池，按稀有度权重随机抽 3 个【不重复】项
- 过滤：已满 MaxStack 的、与已拥有项互斥的，不再出现

===== 七、数值设计的硬约束（务必在给建议时检查） =====
- 【吸血悬崖】每次撞击净耗 = 1 − Y/X。当 Y/X ≥ 1 时无限续航、游戏崩坏。
  → 任何吸血建议必须满足 X ≥ 2 且 Y < X。
- 【加速反弹】已实现衰减：第 n 次反弹增量 = AccelBase × AccelDecay^(n−1)，硬顶 AccelCap。
  → 不要建议改成固定增量，那会指数爆炸。
- 【敌人强化】所有敌人 buff 必须有 MaxStack 上限。
- 手感参数（加速度/摩擦/顿帧/震屏）暂缓调优，我明确要求时再动。

===== 八、词条 .tres 模板（照抄改数值即可，注意是纯文本，VS Code 直接写） =====

[gd_resource type="Resource" script_class="PlayerUpgradeData" load_steps=2 format=3]

[ext_resource type="Script" path="res://src/Upgrades/PlayerUpgradeData.cs" id="1_scr"]

[resource]
script = ExtResource("1_scr")
DisplayName = "迅捷"
Description = "移动速度 +15%"
Rarity = 0
MaxStack = 5
IsMechanic = false
Stat = 1
Op = 1
Value = 0.15

敌人线，存为 data/enemy_upgrades/xxx.tres：把 script_class 与 path 换成
EnemyUpgradeData / res://src/Upgrades/EnemyUpgradeData.cs，Stat 用 EnemyStat 的序号。

字段含义：
  Rarity    0=Common 1=Rare 2=Epic（.tres 里写数字，不要写名字）
  Op        0=Add（Base+ΣAdd）1=Mul（(Base+ΣAdd)×(1+ΣMul)）2=Override（最后生效，直接定为 Value）
  Stat      PlayerStat/EnemyStat 枚举的【序号】，从 0 开始数，见 src/Core/PlayerStat.cs
  IsMechanic true = 机制类，参与"保底至少 1 个机制类"
⚠️ .tres 里写错格式 Godot 会 Parse Error 且报错信息很难懂。
   拿不准时让我用 Godot 编辑器"新建资源"生成，再照着它的格式改。
